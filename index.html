MODULE 01 · CORE DEFINITION

從「只會回答問題的顧問」進化為「具備手腳的數位專案經理」

OpenAI Lilian Weng 經典 Agent 架構公式
AI Agent = LLM (核心大腦) + Planning (規劃與反思) + Memory (長短期記憶) + Tools (工具調用)

傳統 LLM 對話是「被動回應（你問一句、它答一句）」；而 AI Agent 則是「目標導向（Goal-Driven）」——你只需給定終極目標（例如：挽留高流失 VIP 且 ROAS 需達 2.0 以上），它就能自己拆解步驟、呼叫外部工具查資料庫、發現不達標自動重算，直到交付最終決策報告。

比較維度 第一代：傳統 Chatbot (單純 LLM) 第二代：傳統 RPA 流程自動化 第三代：AI Agent (自主智慧代理)
1. 驅動方式 提示詞驅動 (Prompt-Driven)：仰賴人類逐步輸入指令推進。 規則驅動 (Rule-Driven)：死板的固定腳本，無法理解語意。 目標驅動 (Goal-Driven)：給定終極商業目標後自主拆解多輪任務。
2. 思考與反思 單次線性輸出，缺乏事後自我檢討與驗證能力。 零思考能力，遇到網頁改版或異常數值即報錯停機。 具備 ReAct 自我反思迴圈，發現 ROAS 不足或違規會主動調參重試。
3. 外部行動力 封閉於對話視窗內，僅能生成文字或程式碼片段。 僅能按固定座標點擊或複製貼上固定表格欄位。 透過 Function Calling 自主決定何時查 CRM、算財務模型或派工單。
4. 記憶狀態 僅限當下 Context Window，關閉即失憶。 無語意記憶，僅有執行 Log。 結合短期任務狀態黑板 (Shared State) 與長期向量/Firestore 記憶庫。
5. 企業定位 個人文書與靈感助手。 高重複性表單搬運工。 跨部門端到端流程重構的「數位勞動力 (Digital Workforce)」。

            MODULE 04 · FUNCTION CALLING PROTOCOL
            
解剖 Gemini Function Calling 三階段技術握手協議

          

          
        


        

          

            
STEP A：遞交工具說明書 (functionDeclarations)

            
前端發送請求時附上本地函數名稱與參數規格：

            
{
  "name": "calculateCampaignROI",
  "description": "試算行銷活動 ROAS 與預估營收",
  "parameters": {
    "type": "OBJECT",
    "properties": {
      "budget": { "type": "NUMBER" },
      "cpc": { "type": "NUMBER" },
      "cvr": { "type": "NUMBER" }
    }
  }
}

          


          

            
STEP B：模型決定呼叫工具 (functionCall)

            
Gemini 判斷需先算財務模型，回傳 JSON 結構化指令：

            
{
  "functionCall": {
    "name": "calculateCampaignROI",
    "args": {
      "budget": 500000,
      "cpc": 35,
      "cvr": 0.008
    }
  }
}

          


          

            
STEP C：本地執行並餵回結果 (functionResponse)

            
本地 JS 算出 ROAS 過低，回傳警告觸發下一輪反思：

            
{
  "functionResponse": {
    "name": "calculateCampaignROI",
    "response": {
      "roas": 1.03,
      "status": "WARNING_LOW_ROAS_NEEDS_REFLECTION"
    }
  }
}

          

        

      


      
      

        

          

            MODULE 05 · TONY'S 4R METHODOLOGY
            
TONY 楊文澤老師獨創：「企業 AI Agent 流程重構 4R 法則」

          

          
        


        

          

            
R1 · Recognize（痛點盤點與任務邊界識別）

            
盤點企業內部「高重複性、需跨系統查詢、且具備明確量化驗收標準」的知識型決策節點（例如：VIP 流失挽留試算、廣告法規禁用詞審查），避免一開始就做邊界模糊的空泛 AI。

          

          

            
R2 · Redesign（人機協作與多代理職能重構）

            
將單一巨型 Prompt 拆解為「單一 Agent 工具箱（STEP 2）」或「策略 ➔ 文案 ➔ 視覺 ➔ 審核 4-Agent 專職團隊（STEP 3）」，透過結構化 JSON 黑板確保交接零失真。

          

          

            
R3 · Reflect（量化檢核點與自我反思閉環設計）

            
在工具回傳值中植入「風控護欄（Guardrails）」——當 `ROAS < 2.0` 或 `法遵評分 < 85` 時，強制觸發 ReAct 反思重算或精準局部退件（Targeted Rollback）。

          

          

            
R4 · Realize（高階決策交付與商業價值變現）

            
將最終通過審核之狀態黑板自動匯聚為「麥肯錫級高階決策備忘錄」或「整合行銷企劃書 Word 檔」，並直接派發跨部門工單，實現商業價值落地。
