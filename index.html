Module 01 / Foundation

什麼是 AI Agent？從「博學的對話顧問」進化為「具執行力的數位專案經理」

過去：傳統生成式 AI (LLM Chatbot)
博學但被動的「問答顧問」

你問一句、它答一句（Prompt → Response）。它被關在對話視窗裡，無法主動查證最新企業資料庫、不會自己按計算機驗算財務報表，若給出錯誤建議也不會自我反省。

現在：AI Agent (自主智慧代理)
自主閉環的「數位專案經理」

你只需下達終極目標 (Goal)，Agent 能自己拆解步驟、主動調用外部工具 API、檢視執行結果；發現 ROAS 不達標時會啟動自我反思 (Self-Reflection) 修改參數重試，直到交付合格成果！

Lilian Weng (OpenAI) 經典 AI Agent 核心架構公式
AI Agent = LLM (核心大腦) + Planning (規劃與反思) + Memory (短長期記憶) + Tools (工具調用)

企業轉型必懂：傳統 Chatbot、RPA 流程自動化與 AI Agent 五維度對比

比較維度 傳統 LLM 對話機器人 傳統 RPA (如固定腳本爬蟲) AI Agent (自主智慧代理)
1. 驅動方式 依賴人類逐步輸入 Prompt 推進 依賴工程師寫死 If-Else 規則 給定高階目標 (Goal)，自主拆解多步任務
2. 思考與反思 單次生成，不驗算結果對錯 無語意理解力，只照腳本點按 具備 ReAct 自我反思，未達標會修正重試
3. 外部環境邊界 封閉於對話框，僅產出文字/圖片 可操作固定軟體介面 透過 Function Calling 動態操作 API 與資料庫
4. 例外狀況處理 容易產生幻覺 (Hallucination) 網頁改版或參數異常即直接當機報錯 觀察錯誤訊息後動態調整策略繞道解決
5. 記憶系統 僅限當下對話視窗 無狀態記憶 短期多輪狀態記憶 + 長期向量資料庫 (RAG)

Module 03 / ReAct Loop Simulator

ReAct 狀態反思迴圈（Reason + Act）：為什麼 Agent 不會將錯就錯？

ReAct 框架（由 Yao et al. 提出）是現代 AI Agent 最核心的運作機制。它讓模型交替進行「Reasoning（邏輯推理產生 Thought）」與「Acting（呼叫外部工具 Action）」，並根據工具回傳的「Observation（環境觀察結果）」決定要繼續修正參數還是產出最終報告。請點擊下方「下一步」體驗完整 5 階段閉環：

Module 04 / Function Calling Mechanics

Function Calling (工具調用) 技術解密：LLM 究竟是如何「呼叫」你的 JavaScript 函數？

課堂最常見迷思破除： Gemini 模型伺服器並不會直接連進你的電腦或企業內網執行程式碼！真正的運作方式是：我們先把本地工具有哪些參數（functionDeclarations JSON Schema）告訴 Gemini；當 Gemini 判斷需要查資料時，它會回傳一段結構化的 functionCall JSON（告訴你：「請幫我執行 calculateCampaignROI 並帶入這些參數」），接著由我們前端的 JavaScript 執行完畢後，再把結果透過 functionResponse 傳回給 Gemini！
STEP A：我們向 Gemini 宣告工具菜單
tools: [{
  functionDeclarations: [{
    name: "calculateCampaignROI",
    description: "試算行銷ROAS與淨利",
    parameters: {
      type: "OBJECT",
      properties: {
        budget: { type: "NUMBER" },
        targetCPC: { type: "NUMBER" },
        conversionRate: { type: "NUMBER" },
        avgOrderValue: { type: "NUMBER" }
      }
    }
  }]
}]
STEP B：Gemini 回傳請求調用指令
// 模型不回傳一般文字，而是回傳：
"functionCall": {
  "name": "calculateCampaignROI",
  "args": {
    "budget": 50000,
    "targetCPC": 2.5,
    "conversionRate": 1.2,
    "avgOrderValue": 120
  }
}
STEP C：本地 JS 執行並塞回結果
// 本地函數精算後回傳給模型：
"functionResponse": {
  "name": "calculateCampaignROI",
  "response": {
    "status": "WARNING_LOW_ROAS",
    "ROAS": 0.58,
    "hint": "請調優參數重試！"
  }
}
Module 05 / TONY's 4R Framework

TONY 楊文澤老師獨創：「企業 AI Agent 流程重構 4R 法則」與 Multi-Agent 協作藍圖

企業導入 AI Agent 最怕「為了技術而技術」。TONY 老師結合台大 EMBA 與多家上市櫃企業內訓經驗，歸納出將傳統人工流程轉化為自主 Agent 工作流的 「4R 流程重構法則」：

STEP 01 / RECOGNIZE

1. 盤點識別 (Recognize) — 鎖定高價值斷點

找出企業內部「跨系統查詢、需要初步數據試算、且常因人工疏忽導致決策延誤」的流程節點（例如：廣告 ROAS 異常巡檢、競品破盤監測、高資產保戶異議應對）。

STEP 02 / REDESIGN

2. 拆解重構 (Redesign) — 經驗工具化 (Toolification)

將資深主管腦中的隱性知識，拆解為標準化的 Tool 函數（如本工作台的 queryBrandMetrics、calculateCampaignROI），讓 AI 有明確的外部算力可調用。

STEP 03 / REFLECT

3. 反思閉環 (Reflect) — 植入守門員檢核指標

為工具回傳值設定明確的商業紅綠燈門檻（例如：ROAS < 2.0 自動回傳 WARNING_LOW_ROAS），強制 Agent 在交付人類前先自我修正。

STEP 04 / REALIZE

4. 價值變現 (Realize) — 連結派工與決策報告

Agent 的終點不能只是聊天文字，必須直接觸發企業派工單（createActionTicket）並產出可呈報董事會的結構化 Word 決策報告，真正落地商業價值。

課堂教學講義模式

Vanilla JS 實作 Gemini Function Calling 與 ReAct 狀態反思迴圈核心架構

TONY 老師課堂重點提示： 傳統對話式 AI 只有一次性的 Prompt → Response；而 AI Agent 的靈魂在於下方的 while (iteration < maxIterations) 狀態迴圈。只要模型回傳 functionCall，前端或後端就會攔截並執行本地工具，再將 functionResponse 塞回對話歷史中，讓模型自我反思是否需要修正參數再呼叫一次！ 
// 1. 定義主模型與自動降級備援模型 (Exponential Backoff + Fallback)
const PRIMARY_MODEL = "gemini-3.8-flash";
const FALLBACK_MODEL = "gemini-3.5-flash";

// 2. 核心 ReAct 自主狀態迴圈 (Vanilla JS While Loop)
async function runReActAgentLoop(userGoal, maxIterations = 5) {
  const contents = [{ role: "user", parts: [{ text: userGoal }] }];
  let iteration = 0;

  while (iteration < maxIterations) {
    iteration++;
    const response = await callGeminiWithFallback(contents, agentTools);
    const candidate = response.candidates[0];
    contents.push(candidate.content);

    const functionCalls = candidate.content.parts.filter(p => p.functionCall);
    if (functionCalls.length === 0) {
      return candidate.content.parts.map(p => p.text).join("\n");
    }

    const toolResponseParts = [];
    for (const part of functionCalls) {
      const { name, args } = part.functionCall;
      const result = await localToolRegistry[name](args);
      toolResponseParts.push({
        functionResponse: { name, response: { result } }
      });
    }
    contents.push({ role: "user", parts: toolResponseParts });
  }
}
